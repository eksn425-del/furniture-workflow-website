## 交接反馈与源码核对结果

交接包相对基线包含 18 个实质源码修改。其余大量字节差异来自换行符或 BOM，不作为功能变更合入。有效变化集中在以下部分：

1. 目标数量与类目配额
   - `TOTAL_ACROSS_SELECTED + EVEN` 将总目标 N 分配到已选类目，各类目配额之和严格等于 N。
   - `PER_CATEGORY` 继续表示每个类目各自满足 N，总量为 N × 类目数。
   - 某个已选类目证据耗尽后，允许其他已选类目在不突破总目标的前提下补位。
   - REQUIRED 配额同时保持范围锁，未选类目不能消耗目标或补位缺口。

2. 数量不足与恢复
   - Exact-N 不足会保留 `TARGET_SHORTAGE` 与结构化决策事件，不伪造成功。
   - 操作员可明确接受当前完成数量，再恢复同一 Job 进入交付。
   - 接受缺额的决定写入持久 Job Policy，并在恢复时进入新的运行契约。

3. L2 浏览器生命周期
   - 默认先使用持久化无头会话，减少对操作员桌面的干扰。
   - 只有检测到明确、可见的访问验证控件时，才切换到同一持久会话目录的可见浏览器。
   - 临时技术故障执行有界重试；持续失败后保留 checkpoint，不尝试绕过 CAPTCHA、登录或 WAF。

4. 类目范围与数量显示
   - 父级与其子级同时选择时，子级收窄父级，避免同一范围重复采集和重复计数。
   - 被子级收窄的 UNKNOWN 父级不再让已选数量错误显示为 UNKNOWN。
   - Candidate 的所选类目身份与 Brain 语义类目分开保存，避免配额 key 被视觉语义覆盖。

5. 品牌库命名
   - 新建任务可显式标记品牌官方网站并保存品牌名。
   - 品牌库优先采用品牌前缀、官方商品名和视觉属性组成最终名称。
   - 品牌已包含在官方名开头时不会重复添加；最终名称继续执行含空格不超过 50 字符的 Production Gate。

6. 尺寸与 Blender
   - 官方结构化尺寸和官方页面尺寸仍优先。
   - 官网完全没有尺寸时，Brain 可提供 `AI_ESTIMATED` 高度；不得把估算伪装为官方证据。
   - 一个或两个可靠尺寸轴可作为等比缩放锚点；冲突轴需要明显非等比拉伸时进入 `MODEL_DIMENSION_CONFLICT`，不会强行变形。

7. 交付与 UI
   - Pipeline Timeline 改为纵向线性阶段，并补充筛选、尺寸、入库和 Provider 进度事件。
   - 每批最多 20 个 GLB；下载 ZIP 只包含 GLB，JSON manifest 作为独立可审计 Artifact 保留。
   - ZIP 使用任务名、Job ID 和批次组成唯一文件名；下载响应支持中文和空格文件名。

## 对交接实现做的安全修正

交接源码曾把付费 Provider 的默认成本上限自动审批。公开仓库没有采用这一行为：

- Provider OFF 仍可直接形成 Ready Pool，不产生付费调用。
- 付费 Provider 必须由操作员明确确认成本上限后才可启动。
- Provider ledger、资格检查和幂等提交规则保持不变。

另外修复了交接包中发现的边界问题：

- REQUIRED 配额不再接受未选类目的候选。
- 部分官方尺寸不会被 AI 高度估算覆盖。
- 品牌前缀不会与官方名称重复。
- 缺额接受动作会真正写入恢复契约，而不是提前把 Job 标记为完成。
- “ZIP 仅含 GLB”的新交付契约与端到端测试保持一致。

## 当前能力边界

这次对齐提高了 Website 的目标分配、恢复、浏览器生命周期、品牌命名、尺寸归一化和交付一致性，但不代表任意第三方站点都必然成功。CAPTCHA、登录、WAF、站点离线、robots 限制和未知结构仍需真实分类为 `HUMAN_REQUIRED`、`ACCESS_CHANGE_REQUIRED`、`SITE_OFFLINE`、`ROBOTS_DENIED` 或 `UNSUPPORTED_STRUCTURE`，不得伪造数量或产品。

公司环境接入时仍需在本机通过环境配置提供 Brain/Vision、Lux3D 和 Blender；公开仓库只保留变量名、配置模板和安全启动逻辑，不包含真实凭据。
